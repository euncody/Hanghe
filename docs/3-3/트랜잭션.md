\*\*트랜잭션(Transaction)\*\*은 **데이터베이스에서 여러 작업을 하나의 논리적인 단위로 묶어 처리하는 것**을 의미합니다.
즉, 여러 개의 쿼리(INSERT, UPDATE, DELETE 등)를 “모두 성공하거나 모두 실패”하게 만들어 **데이터의 일관성과 무결성**을 보장하는 기술이에요.

---

### **1. 트랜잭션의 기본 개념**

트랜잭션은 보통 아래 네 가지 성질(**ACID**)을 가집니다.

| 속성                    | 설명                              | 예시                             |
| --------------------- | ------------------------------- | ------------------------------ |
| **Atomicity (원자성)**   | 모든 작업이 한 번에 처리되거나 전혀 처리되지 않아야 함 | 예약·결제 중간에 오류 나면 모든 변경사항을 롤백    |
| **Consistency (일관성)** | 트랜잭션이 끝나면 데이터는 항상 유효한 상태여야 함    | 재고가 음수가 되지 않도록 보장              |
| **Isolation (고립성)**   | 동시에 여러 트랜잭션이 실행돼도 서로 간섭하지 않음    | 두 사용자가 같은 책을 동시에 예약해도 중복 없이 처리 |
| **Durability (영속성)**  | 커밋된 데이터는 시스템 장애가 나도 유지          | 결제 완료 후 서버가 다운돼도 기록은 남아 있음     |

---

### **2. 트랜잭션의 동작 예시**

**예: 도서 예약 로직**

1. 예약 테이블에 사용자 예약 기록 추가
2. 재고 테이블에서 해당 도서 수량 감소
3. 포인트 적립 내역 기록
4. 모든 작업이 성공하면 `COMMIT`
   하나라도 실패하면 `ROLLBACK`

이렇게 한 덩어리로 묶은 단위를 “트랜잭션”이라고 합니다.

---

### **3. 트랜잭션이 중요한 이유**

* **데이터 무결성 보장**: 중간에 서버가 죽어도 데이터가 꼬이지 않음
* **에러 처리 용이**: 문제가 생기면 한 번에 `ROLLBACK`으로 원상복구 가능
* **동시성 관리**: 여러 사용자가 동시에 작업해도 충돌을 최소화

---

### **4. 트랜잭션을 가볍게 유지해야 하는 이유**

트랜잭션은 유지되는 동안 DB가 관련 리소스를 잠그기 때문에:

* 트랜잭션이 길어지면 \*\*락(Lock)\*\*이 오래 유지됨 → 다른 요청이 대기
* **장애 전파** 가능성 증가 → 일부 부가 로직 때문에 핵심 로직까지 실패
* 성능 저하 발생 → TPS(초당 처리 건수) 하락

---

### **5. 개발 관점에서의 트랜잭션**

* **Java/Spring**: `@Transactional` 애너테이션으로 시작\~종료 범위 지정
* **MyBatis**: `SqlSession`으로 `commit()`/`rollback()` 명시
* **SQL**: `BEGIN TRANSACTION` → 작업 → `COMMIT` 또는 `ROLLBACK`

---

즉, 트랜잭션은 \*\*“데이터를 신뢰할 수 있는 상태로 유지하기 위한 안전장치”\*\*라고 이해하면 됩니다.
