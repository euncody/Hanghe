## 1. 메시지 브로커란?

* **정의**:
  메시지 브로커는 **애플리케이션, 서비스, 시스템 간의 데이터(메시지)를 중개하고 전달하는 미들웨어**입니다.
  → 쉽게 말해, **“데이터 택배 기사”** 역할을 하는 소프트웨어예요.

* **필요성**:
  보통 시스템 간 직접 통신을 하면 서로 강하게 묶여(결합) 버립니다.
  메시지 브로커를 두면, 송신자(Producer)와 수신자(Consumer)가 직접 연결되지 않고 **느슨하게 결합(Loosely Coupled)** 되어 시스템을 더 유연하게 만들 수 있습니다.

---

## 2. 메시지 브로커의 동작 방식

1. **Producer**: 데이터를 생성하고 브로커에 보냄
2. **Broker**: 받은 데이터를 **임시 저장**하고, 정해진 규칙(큐, 토픽 등)에 따라 관리
3. **Consumer**: 브로커에서 메시지를 꺼내 사용

👉 즉, Producer는 “누가 이걸 가져갈지” 알 필요 없고, Consumer도 “누가 보냈는지” 알 필요 없음 → 브로커가 알아서 연결.

---

## 3. 메시지 브로커의 주요 기능

* **메시지 전달**: 한 시스템에서 보낸 메시지를 다른 시스템으로 안전하게 전달
* **비동기 처리**: 메시지를 즉시 처리하지 않아도, 나중에 Consumer가 가져갈 수 있음
* **버퍼링(Buffering)**: 트래픽이 몰려도 메시지를 큐에 쌓아두고 천천히 처리 가능
* **라우팅(Routing)**: 메시지를 특정 조건(토픽, 규칙 등)에 따라 다른 Consumer에게 분배
* **내구성(Durability)**: 디스크에 저장하여 장애 발생 시 데이터 손실 최소화
* **확장성(Scalability)**: 여러 Producer와 Consumer를 동시에 처리 가능

---

## 4. 메시지 브로커의 유형

1. **메시지 큐 기반 (Message Queue)**

    * 메시지를 순서대로 큐에 저장
    * Consumer가 꺼내면 메시지가 삭제됨
    * 예시: RabbitMQ, ActiveMQ, AWS SQS

2. **퍼블리시/서브스크라이브 기반 (Pub/Sub)**

    * Producer는 특정 주제(Topic)에 메시지를 발행(Publish)
    * 여러 Consumer가 그 주제를 구독(Subscribe)해서 같은 메시지를 동시에 수신 가능
    * 예시: Kafka, Google Pub/Sub

---

## 5. 메시지 브로커를 사용하는 이유

* **시스템 간 결합도 낮춤** → 유지보수성과 확장성이 올라감
* **대규모 트래픽 안정 처리** → 갑자기 요청이 몰려도 브로커가 버퍼 역할 수행
* **비동기 처리** → 사용자 요청에 즉시 응답하고, 실제 작업은 나중에 처리 가능 (예: 이메일 전송)
* **확장성** → 여러 서버, 여러 애플리케이션이 동시에 연결 가능

---

📌 **정리**
메시지 브로커는 **시스템 간 데이터 전달을 중개**하는 소프트웨어로,
👉 **느슨한 결합, 비동기 처리, 트래픽 분산, 확장성**을 제공하여 **대규모 분산 시스템의 핵심 인프라** 역할을 합니다.
