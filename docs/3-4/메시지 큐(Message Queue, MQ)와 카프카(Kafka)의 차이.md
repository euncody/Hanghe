## 1. 메시지 큐 (Message Queue, MQ)

* **정의**:
  메시지를 임시 저장했다가, 소비자(Consumer)가 가져가도록 해주는 중간 저장소.
* **동작 방식**:

    * **FIFO(First In, First Out)** 방식으로 메시지를 꺼내감.
    * 보통 한 메시지는 **한 소비자만** 가져가고, 가져간 순간 큐에서 삭제됨.
* **대표 예시**: RabbitMQ, ActiveMQ, AWS SQS

👉 **비유**:
택배 창고에 박스(메시지)를 쌓아두면, 택배기사(Consumer)가 하나씩 가져가서 배송하는 방식.

---

## 2. 카프카 (Apache Kafka)

* **정의**:
  단순 큐가 아니라, **분산 로그 기반 스트리밍 플랫폼**.
* **동작 방식**:

    * 메시지를 **디스크에 로그 형태로 저장** → 일정 기간 동안 삭제되지 않음.
    * 여러 Consumer Group이 **같은 메시지를 동시에** 읽을 수 있음.
    * Topic을 **Partition** 단위로 나눠서 병렬 처리 가능.
* **대표 활용**: 실시간 로그 수집, 빅데이터 파이프라인, 이벤트 스트리밍

👉 **비유**:
컨베이어 벨트에 물건(메시지)이 계속 흘러가고, 여러 작업자(Consumer Group)가 각자 필요한 구간에서 물건을 가져가는 방식. 물건은 사라지지 않고 일정 시간 동안 계속 남아있음.

## 3. MQ vs Kafka 차이점 요약

| 구분         | 메시지 큐 (MQ)               | 카프카 (Kafka)                         |
| ---------- | ------------------------ | ----------------------------------- |
| **데이터 저장** | 메시지를 소비하면 삭제됨            | 메시지를 로그에 기록, 일정 기간 유지               |
| **소비 방식**  | 보통 1개의 Consumer만 메시지를 소비 | 여러 Consumer Group이 같은 메시지를 각각 소비 가능 |
| **처리 모델**  | 큐 기반 (Point-to-Point)    | 로그 스트리밍 기반 (Pub-Sub + 로그 저장)        |
| **확장성**    | 단일 큐 중심, 확장성 제한적         | 분산 시스템 기반, 파티션으로 무한 확장 가능           |
| **활용 분야**  | 간단한 작업 분배, 비동기 처리        | 대용량 데이터 파이프라인, 실시간 이벤트 처리           |
| **대표 기술**  | RabbitMQ, ActiveMQ, SQS  | Apache Kafka                        |

---

📌 **정리**

* **MQ**: 단순히 “메시지를 전달하고 소비되면 끝” → 업무 큐, 알림 전달, 간단한 비동기 처리에 적합.
* **Kafka**: “메시지를 저장하고, 여러 시스템이 동시에 읽고, 대규모로 확장 가능” → 로그 수집, 빅데이터 처리, 실시간 분석에 적합.
