

## 1. 카프카의 정의와 특징

* **정의**:
  Apache Kafka는 분산 메시지 스트리밍 플랫폼으로, 대용량 데이터를 빠르고 안정적으로 **발행(Publish) / 구독(Subscribe)** 하여 **실시간 처리**할 수 있도록 돕는 메시지 브로커(Message Broker) 시스템입니다.

* **주요 특징**

    * **메시지 브로커**: Producer가 보낸 메시지를 Topic에 저장하고 Consumer가 가져가도록 중개.
    * **고가용성**: 여러 Broker와 파티션 복제를 통해 장애 시에도 서비스 지속 가능.
    * **비동기 처리**: Producer와 Consumer가 직접 연결되지 않고, Kafka를 통해 느슨하게 결합 → 대규모 시스템 확장에 유리.
    * **분산 시스템**: 여러 서버에 걸쳐 데이터를 저장/처리 → 대용량 데이터 처리와 확장성 제공.
    * **내구성 & 안정성**: 디스크에 메시지를 Commit Log 형태로 저장해 장애 발생 시에도 데이터 유실을 최소화.

---

## 2. 카프카의 구성 요소

* **Broker**

    * Kafka 서버 자체. Producer/Consumer의 요청을 처리하고 메시지를 저장/전달.
    * 여러 개의 Broker가 모여 클러스터를 형성하며, 노드 확장으로 성능과 안정성을 확보.

* **Topic & Partition**

    * **Topic**: 메시지를 분류하는 논리적 단위 (예: 주문, 결제, 로그).
    * **Partition**: 하나의 Topic을 여러 조각으로 나눠 저장 → 병렬 처리와 성능 향상.
    * Partition에는 오프셋(Offset)이 있어 Consumer가 어디까지 읽었는지 추적 가능.

* **Producer / Consumer**

    * **Producer**: 메시지를 Topic에 발행하는 클라이언트.
    * **Consumer**: Topic에서 메시지를 구독하는 클라이언트.
    * Consumer는 **Consumer Group**을 형성할 수 있으며, 파티션을 분산해서 병렬 처리 가능.

---

## 3. 대용량 시스템에서 카프카를 사용하는 이유

* **확장성**: Partition 단위로 데이터를 분산 저장하고 Consumer Group으로 병렬 처리 가능 → 초당 수백만 건 메시지도 처리 가능.
* **고가용성**: 복제(Replication)를 통해 장애가 발생해도 데이터 손실을 막고 서비스 지속.
* **실시간 처리**: 대기열 기반이 아니라 스트리밍 구조 → 실시간 로그, 이벤트 처리, 데이터 파이프라인 구축에 최적.
* **느슨한 결합**: Producer와 Consumer가 직접 연결되지 않음 → 서비스 간 종속성을 줄여 마이크로서비스 아키텍처에 적합.
* **내구성 보장**: 디스크에 로그를 Append Only로 기록 → 장애 복구가 용이하고 장기간 데이터 저장 가능.

---

📌 **정리**:
Kafka는 **분산/고가용성 메시지 브로커**로, **Topic-Partition 구조**를 통해 대용량 데이터를 **비동기·실시간**으로 처리할 수 있게 해줍니다.
따라서 **대규모 트래픽 로그 수집, 마이크로서비스 이벤트 전달, 데이터 파이프라인 구축** 등에 널리 사용됩니다.
