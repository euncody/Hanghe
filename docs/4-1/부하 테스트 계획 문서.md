# 성능/부하 테스트 계획서 (초안)

## 1. 목적
- 상품 조회를 목표 응답시간 내 처리 가능한지 검증
- 피크/스파이크 시 병목 지점(DB 잠금, 캐시 미스, 외부 연동 대기, 네트워크 등) 식별
- 용량 산정: 동시 사용자/초당 요청 수 대비 필요한 인프라 추정

## 2. 범위
- In: Public API/웹 백엔드, 검색
- Out: 관리자 백오피스, 배치/ETL, 실제 결제/실물 DRM(모의/스텁 사용)

## 3. 환경(SUT)
- 대상 도메인: http://localhost:8089
- 아키텍처: LB → Web/API → Cache(Redis) → DB(MySQL)
- 전제: 테스트 전용 계정/데이터, 모니터링 대시보드(Grafana/CloudWatch 등)

## 6. 지표/목표
- 오류율 `< 0.5%`
- 응답시간: p95 `<= 800ms`, p99 `<= 1200ms`
- 자원: CPU `< 70%`, Mem `< 80%`, DB 대기/락 지표 모니터링
- 스루풋: 목표 RPS 달성 여부

## 7. 단계
- Smoke(1m) → Load(점증→유지 15m) → Spike(짧은 급증) → Soak(30~60m)

## 8. 리스크
- 실데이터 오염 → 스테이징 + 모의 처리
- 3rd-party 쿼터 소진 → 스텁/레이트리밋
- WAF 차단 → 화이트리스트/테스트 윈도우 협의
